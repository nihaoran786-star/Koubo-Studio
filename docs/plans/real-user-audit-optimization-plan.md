# 真实用户挑刺后的优化计划

## 结论

当前原型视觉方向已经接近“轻量 AI 生成仪器”，但真实用户会在三个地方失去信任：

1. 数据不可保存：项目和文案仍是 mock/组件本地状态。
2. 关键动作是假完成：设备检测、导出成片、发布包都用动画模拟。
3. 设置缺位：模型、隐私、本地文件、桌面权限没有可配置入口。

## 优化顺序

### 第一阶段：先让应用能保存真实项目

对应 issues：005、006、007。

目标是把“创建第一条视频”跑通到可恢复草稿。先不要接复杂模型和渲染，先解决用户最不能接受的数据丢失。

交付结果：
- 新建项目真实落库。
- 文案编辑跨步骤可恢复。
- 空首页不再伪装成已有工作台。

### 第二阶段：建立资产和产物可信度

对应 issues：008、009、010。

目标是让多音频、多视频、字幕、封面和发布包都成为可追踪资产。生成可以先是占位任务，但不能再假装已经真实生成。

交付结果：
- 每个项目有资产列表。
- 渲染导出有任务和产物状态。
- 发布包能真实复制/导出/打开。

### 第三阶段：补设置页和模型接入

对应 issues：011、012。

目标是让用户明确知道当前使用本地模型还是 OpenAI，数据会不会离开本机，设备能力是否支持本地生成。

交付结果：
- OpenAI、本地模型、自定义 endpoint 可配置。
- Provider 可测试连接。
- 设备检测基于真实能力，而不是动画。

### 第四阶段：运营规模化和桌面可信度

对应 issues：013、014。

目标是支持多作品管理，并让 Windows 桌面端具备基本安全、隐私和运行说明。

交付结果：
- 项目列表支持搜索、筛选、排序、批量处理。
- CSP、隐私、README、包名和依赖说明完成。

## 不建议立即做的事

- 不要马上接完整数字人或视频渲染引擎。没有本地项目库和资产模型时，生成结果无法可靠管理。
- 不要继续加视觉动画。当前最大问题不是“看起来不高级”，而是“用户点了以后不知道是否真的发生了”。
- 不要把 OpenAI、本地模型、TTS、FFmpeg 调用直接写进页面组件。必须先有模型 Provider 接口和存储接口。

## 推荐第一批实现范围

第一批只做 005、006、007、011 的最小版本：

- 本地项目库。
- 文案草稿持久化。
- 首次空状态。
- 设置页 Provider 配置壳。

这批完成后，应用会从“演示原型”变成“可以开始真实创作草稿的桌面工具”。
